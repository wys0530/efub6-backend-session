## week13 부하테스트


### [ k6 부하 테스트 결과 ]

### 1. 테스트 개요

k6를 활용하여 API의 성능을 측정하고, 개선 전·후 결과를 비교하였다. 각 시나리오 내에서 동일한 VU, 실행 시간, 요청 간격, thresholds를 적용하여 테스트 조건을 통일하였다.

- **테스트 도구:** k6
- **실행 환경:** GitHub Actions (Ubuntu, Spring Boot, MySQL)
- **테스트 데이터:** 게시글 10,000개
- **테스트 시나리오**
    1. 전체 게시글 조회와 페이지네이션 조회 성능 비교
    2. 단일 카운터와 분산 카운터의 조회수 증가 성능 비교

---

### 2. 시나리오 1: 전체 게시글 조회와 페이지네이션 조회 비교

전체 게시글을 한 번에 반환하는 API와 페이지네이션을 적용하여 일부 게시글만 반환하는 API의 성능을 비교하였다.

#### 테스트 조건

| 항목 | 설정 |
|---|---|
| 개선 전 API | `GET /posts/all` |
| 개선 후 API | `GET /posts?page=0&size=20` |
| 최대 VU | 10 |
| 실행 시간 | 약 50초 (증가 10초 + 유지 30초 + 감소 10초) |
| 요청 간격 | 1초 |
| p95 응답 시간 기준 | 500ms 미만 |
| HTTP 요청 실패율 기준 | 1% 미만 |
| checks 성공률 기준 | 100% |
| 응답 크기 p95 기준 | 100,000 미만 |

#### 테스트 결과

| 측정 항목 | 전체 게시글 조회 | 페이지네이션 조회 | 개선 효과 |
|---|---:|---:|---|
| p95 응답 시간(ms) | 61.78 | 24.77 | 약 59.9% 감소 |
| 처리량(req/s) | 7.75 | 7.98 | 약 2.9% 증가 |
| HTTP 요청 실패율(%) | 0 | 0 | 동일 |
| 응답 크기 지표 p95 | 857,818 | 1,814 | 약 99.8% 감소 |
| thresholds 통과 여부 | FAIL | PASS | 기준 충족 |
| 총 HTTP 요청 | 391건 | 400건 | - |

#### 결과 분석

전체 게시글 조회와 페이지네이션 조회를 동일한 부하 조건에서 비교한 결과, 페이지네이션 적용 후 p95 응답 시간은 61.78ms에서 24.77ms로 약 59.9% 감소하였고, 처리량은 7.75req/s에서 7.98req/s로 약 2.9% 증가하였다.

특히 응답 크기 p95는 857,818에서 1,814로 약 99.8% 감소하여 가장 큰 개선 효과를 보였다. 두 테스트 모두 HTTP 요청 실패율은 0%였으나, 전체 게시글 조회는 응답 크기 기준을 초과하여 thresholds를 통과하지 못한 반면, 페이지네이션 조회는 모든 기준을 충족하였다.

이를 통해 페이지네이션을 적용하면 한 번에 반환하는 데이터의 양을 줄여 응답 시간과 데이터 전송 부담을 개선할 수 있음을 확인하였다.

---

### 3. 시나리오 2: 단일 카운터와 분산 카운터 성능 비교

하나의 게시글 조회수를 단일 카운터 행에서 갱신하는 방식과 여러 카운터 행에 분산하여 갱신하는 방식의 성능을 비교하였다.

#### 테스트 조건

| 항목 | 설정 |
|---|---|
| 개선 전 | 단일 카운터 방식 (`hot-row-before`) |
| 개선 후 | 분산 카운터 방식 (`hot-row-after`) |
| 최대 VU | 10 |
| 실행 시간 | 약 40초 (증가 10초 + 유지 20초 + 감소 10초) |
| 요청 간격 | 0.1초 |
| row_update_duration p95 기준 | 500ms 미만 |
| HTTP 요청 실패율 기준 | 1% 미만 |
| checks 성공률 기준 | 100% |

#### 테스트 결과

| 측정 항목 | 단일 카운터 | 분산 카운터 | 개선 효과 |
|---|---:|---:|---|
| row_update_duration p95(ms) | 7.44 | 4.78 | 약 35.8% 감소 |
| 처리량(req/s) | 72.47 | 73.18 | 약 1.0% 증가 |
| HTTP 요청 실패율(%) | 0 | 0 | 동일 |
| thresholds 통과 여부 | PASS | PASS | 동일 |
| 총 HTTP 요청 | 2,903건 | 2,932건 | - |

※ `row_update_duration`은 조회수 증가 요청의 HTTP 응답 시간을 측정한 커스텀 지표로, DB 내부의 UPDATE 실행 시간만을 의미하지 않는다.

#### 결과 분석

단일 카운터 방식과 분산 카운터 방식을 동일한 부하 조건에서 비교한 결과, 분산 카운터 적용 후 p95 응답 시간은 7.44ms에서 4.78ms로 약 35.8% 감소하였다. 처리량은 72.47req/s에서 73.18req/s로 약 1.0% 증가하였다.

두 방식 모두 HTTP 요청 실패율 0%를 기록하였으며, 모든 thresholds를 통과하였다.

분산 카운터 방식이 단일 카운터 방식보다 낮은 p95 응답 시간을 기록한 것은 조회수 갱신 요청을 여러 카운터 행으로 분산하여 단일 행에 대한 갱신 집중을 완화하는 방식이 성능 개선에 도움이 될 수 있음을 보여준다.

다만 처리량 증가 폭은 크지 않았으며, 이번 결과만으로 모든 부하 환경에서 분산 카운터가 우수하다고 단정할 수는 없다. 향후 더 높은 동시성 환경에서 추가 테스트를 진행하여 성능 개선 효과를 확인할 필요가 있다.

---

### 4. 테스트 결과 파일

각 테스트의 상세 측정 결과는 k6의 `--summary-export` 옵션으로 생성한 JSON 파일에 저장하였다.

| 파일명 | 설명 |
|---|---|
| `summary-paginated-posts.json` | 페이지네이션 조회 테스트 결과 |
| `summary-hot-row-before.json` | 단일 카운터 테스트 결과 |
| `summary-hot-row-after.json` | 분산 카운터 테스트 결과 |

---

### 5. 최종 결론

두 시나리오 모두 동일한 부하 조건에서 개선 전·후 성능을 비교한 결과, 개선 후 API의 p95 응답 시간이 감소하였다.

- **페이지네이션 적용:** p95 응답 시간 약 59.9% 감소, 응답 크기 약 99.8% 감소
- **분산 카운터 적용:** p95 응답 시간 약 35.8% 감소, 처리량 약 1.0% 증가

페이지네이션은 반환 데이터 크기를 제한하여 응답 성능과 데이터 전송 효율을 개선하였으며, 분산 카운터는 단일 행에 집중되는 조회수 갱신 요청을 분산하여 응답 시간을 줄이는 데 도움이 될 수 있음을 확인하였다.
